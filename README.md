# 钟乳石洞穴微环境巡测

## 启动

```bash
npm install
npm start
```

默认地址：http://localhost:3912

数据保存在`data/db.json`。

## 领域规则

基准与样点档案分离，判定逻辑独立于页面入口（`lib/judgment.js`）：

- **基准版本**：每个样点拥有多版基准，登记`生效时刻`与温度/湿度/CO2的基准值和允许波动（中心 ± 波动构成范围）。
  换季或补录上旬基准时，新增版本并填写其历史生效时刻；版本号按样点自增。
- **巡测判定**：保存巡测时按“发生当天（含当天）已生效的最新版本”取版本，三项**都在范围才正常**，
  任一项超限或当天没有生效基准，状态转`异常待复查`。判定时固化版本快照（版本号、生效时刻、三项范围），台账展示采用哪版基准和三项逐项结果。
- **自动重算**：基准补录或修订后，该样点下所有受影响的巡测和复查记录按新版本重算；
  版本、基准值未变的记录不会重复写历史。
- **人工结论不能盖判定**：`已复查`记录在新版本下再次超限时自动打回`异常待复查`，复查说明保留留痕；
  巡测状态不接受直接改判（PATCH 返回 405），完成复查前服务端会按当前版本重判，仍超限则拒绝。
- 被巡测引用过的基准版本不可删除（可再补录新版本覆盖）。

## 页面入口

- **趋势看板**：异常待复查事项与汇总统计
- **样点档案**：洞穴、分区、样点、敏感等级、保护状态（不再保存基准值）
- **基准版本**：补录/修订基准，填写生效时刻与三项基准值、允许波动，卡片显示版本生效区间
- **巡测台账**：登记巡测（状态自动判定），卡片展示采用版本、三项逐项范围结果与复查痕迹
